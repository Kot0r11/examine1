# 第 0 部分：给完全零基础的你（先看这个）

## 0.1 造一颗芯片，到底在造什么？

你可以把"造芯片"类比成"盖一栋楼"：

| 盖楼 | 造芯片 |
|---|---|
| 先画建筑设计图（几层、几个房间、管线怎么走） | 先写 **RTL**（用代码描述电路：有几个寄存器、数据怎么流动） |
| 结构工程师验算：这栋楼站得稳吗？ | **仿真**：这段代码描述的电路，功能对不对？ |
| 把设计图交给施工方，用真实的砖、钢筋、水泥去实现 | **综合**：把代码翻译成真实工艺库里的"门电路"（与非门、触发器等） |
| 画施工图：每块砖放在哪里、管线怎么排布 | **布局布线（PnR）**：每个门电路放在芯片的哪个坐标、线怎么连 |
| 出最终施工图纸，交给工厂 | 出 **GDS** 版图文件，交给晶圆厂（**流片 / tapeout**） |
| 质检：符合建筑规范吗？ | **DRC / LVS**：符合工艺制造规则吗？电路连接和设计一致吗？ |

## 0.2 这篇论文要解决的"痛点"

过去想学造芯片，你得有：

1. **商业 EDA 软件授权** —— Synopsys、Cadence 这些公司的工具，一套授权几百万，学校买不起就开不了课；
2. **NDA 保密的 PDK** —— "工艺设计套件"，简单说就是晶圆厂给你的"零件目录 + 制造规则"，签了保密协议才能拿，管理极其麻烦；
3. **闭源的硬件 IP** —— 现成的处理器核、外设模块，别人不给你源代码。

结果：**全世界只有极少数学校能开"真的把芯片造出来"的课**，绝大多数学生只能学理论，或者玩 FPGA（可编程逻辑阵列，不算真造芯片）。

## 0.3 论文的答案

> **做一个完全开源的、为教学设计的 RISC-V SoC 模板（叫 Croc），配一条全开源的 RTL→GDS 流程，用完全开源的 130nm 工艺库，让任何学校都能开"造真芯片"的课。**

并且他们真的做了：2025 年春季学期，65 个学生做了 33 个芯片项目，**5 颗真的拿去工厂流片了**，其中一颗已经在实验室里点亮并测出性能。

## 标题与作者

**Croc：用"领域定制的端到端开源硅片"培养下一代芯片设计师**

Enrico Zelioli、Philippe Sauter、Thomas Benz、Hannah Pochert、Luisa Wüthrich、Beat Muheim、Frank K. Gürkaynak、Luca Benini
（* 苏黎世联邦理工 ETH Zurich，瑞士；† lowRISC C.I.C.，英国；‡ 博洛尼亚大学，意大利）
所有作者贡献相同。

## 摘要

人工智能、机器人和汽车系统对**领域定制系统级芯片（domain-specific SoC）**的需求不断增长，因而越来越需要这样的工程师：他们具备从架构定义一直到**流片制造**的**超大规模集成电路（VLSI）设计**实战经验。

然而，大多数 VLSI 课程依赖**授权受限的 EDA 工具**和**工艺设计套件（PDK）**，以及**闭源的硬件设计**。

我们提出一套**端到端开源的领域定制 SoC 设计与制造流程**，它围绕 **Croc** 构建 —— 一个高度可定制的 RISC-V 平台。Croc 由**开源 SystemVerilog IP 模块**搭建而成，并与一条**端到端的开源设计流程**集成，目标是 **130nm 开源 PDK**。Croc 支持流片项目，并提供多种领域定制选项：**指令集扩展**、**加速器协处理器**、**外设**。

在我们使用 Croc 的第一轮开源课程实践中，**65 名学生完成了 33 个项目，其中 30 个产出了可制造的版图**。18 个设计入选流片候选，**5 个成功流片**。第一颗基线芯片已在硅片上成功完成测试（characterized in silicon），展现出**微控制器级别的功能**，其实现指标与"用闭源工具链和 PDK 完成的、功能复杂度相近的产品"相当。

## I. 引言（Introduction）

半导体产业正在加速增长，驱动力是 AI、机器人、汽车应用对**专用领域定制架构（DSA）**不断增长的需求。与此同时，近年的芯片供应链危机清楚地表明：**瓶颈不只是制造产能，还包括具备集成电路（IC）设计与制造实战经验的工程师的供给**[1]。

这一挑战也反映在近期的公共计划中 —— 即所谓的**《芯片法案》（Chips Acts）**[1,2] —— 它们高度重视培训、技能提升，以及降低新一代芯片设计师进行硅原型验证的门槛。随着对硅片的需求持续增长，这种人才短缺预计将是一个**结构性的长期问题**，形成一个明确的教育缺口。为了跟上趋势，半导体产业需要能够培养出**又强又多的下一代芯片设计师**的教育项目[3]。

许多现有的 VLSI 课程依赖**闭源的 EDA 工具授权**、**受 NDA（保密协议）限制的 PDK**，还需要复杂的安全与访问控制基础设施，只有**少数教育机构**才能负担。结果是：**动手做芯片设计的培训只局限于少数被选中的学生或大学**，而其他许多人只能获得理论背景，或者基于 **FPGA**（现场可编程门阵列）的经验[3]。

近期**开源（OS）硬件平台、EDA 工具和开源 PDK**[4]的进展，为芯片设计培训项目创造了新的基础，这比传统的大学课程**更易获得、更易规模化**。开源生态消除了对"有限的商业授权、受 NDA 限制的 PDK、闭源硬件 IP"的需求，从而**降低了 RTL 到 GDS 全流程教育的行政门槛与准入门槛**。这使得培养**规模更大、更多样化的学生群体**成为可能，包括那些本来没有预算、法律框架和技术基础设施去开"基于保密闭源设计环境的硅片课程"的院校。

在这项工作中，我们展示了 **ETH Zurich 在 2025 年重构后的 VLSI 课程第一轮迭代**的成果 —— 该课程围绕一个**完全开源、可复现的教学框架**重新设计。课程的主要目标是提升学生的实践能力，并让"动手做领域定制芯片设计"的教育**更具可扩展性、更容易迁移到单个院校之外**。

课程围绕开源的 **Croc 系统级芯片（SoC）平台**[5]构建。Croc 的模块化架构旨在让学生对 SoC 配置有**细粒度的控制**，并支持领域定制，即：**指令集架构（ISA）扩展**、**加速器协处理器集成**、**专用外设**。除了 SoC 设计本身，Croc 平台还包含一条**端到端的设计流程**，它对新手友好，同时仍允许大量定制。**完整的教学材料和工具流程以知识共享（Creative Commons）许可自由开放**¹，使这种方法**更容易规模化、更容易迁移到其他大学和培训项目**。

> ¹ <https://vlsi.ethz.ch>

## II. Croc SoC 平台（The Croc SoC Platform）

Croc 是一个**微控制器级别（microcontroller-class）的 RISC-V SoC**，构建在**开源的、经过硅验证的 SystemVerilog IP**之上。Croc 被设计为**可扩展且高度灵活**。图 2 展示了 Croc SoC 的顶层架构。设计被分为两个主要部分：**Croc 域（Croc domain）**，包含基础芯片设施；以及**用户域（User domain）**，承载学生的定制设计。Croc 可以从**单一仓库**²获得，其中包含 RTL、软件环境和文档。

**支撑性的 Croc 域**包含：一个由工业界维护的、可用于量产的 **CVE2**[6] RISC-V 核、一组最小化的外设，以及一个 **OBI**[7] 交叉开关（crossbar）。Croc 域主要帮助学生实现、调试和验证他们的设计。学生也可以修改它，例如实现**自定义 ISA 扩展**或**扩展互联**。Croc 具有**单周期的紧耦合互联**和**两个 SRAM bank**，使 CVE2 能够达到**每周期一条指令（1 IPC）**的理想性能。

**用户域**为**松耦合的加速器、协处理器、外设或实验性 RISC-V 核**提供接口。它把主 OBI 交叉开关上的**管理者端口（manager）与从属端口（subordinate）**暴露出来，并提供一组**自定义中断**用于与主机域通信。

Croc 的流程目标是 **IHP 的 130nm 开源 PDK**[8]，使用**完全开源的设计流程**：用 **Yosys** 做综合，用 **OpenROAD** 做物理设计（布局布线），用 **Verilator** 做 RTL 仿真。课程依赖 JKU Linz（林茨开普勒大学）的 **IIC-OSIC-TOOLS**[9] 容器来提供练习所用的开源 EDA 工具。Croc 平台还为 **Digilent 的 Genesys 2 开发板**提供了**开箱即用的 FPGA 仿真（emulation）**，以及一条基于 **nextpnr** 的流程作为端到端开源的替代方案[10]。

我们在第 III 节展示的硅片测试结果，是在一块**原型评估板**上采集的，该板使用 **DUTCTL**[11] 让基于 Croc 的 ASIC **独立运行**。一旦制造出的芯片到货，每个成功流片的小组都会收到一块**评估板**（目前正在开发中），用于支持他们自己芯片的**硅片点亮（bring-up）、测量和应用开发**。

> ² <https://www.github.com/pulp-platform/croc>

## III. 结果（Results）

ETH Zurich 在"动手型 VLSI 设计课程"上有 **35 年以上**的经验，数百颗 ASIC 作为这些课程的一部分被设计出来（使用商业 EDA）。**改版后课程的第一轮迭代证明：一流的 ASIC 设计课程完全可以用开源 EDA 有效地实现。**

在 **2025 年春季学期**，ETH Zurich 的 **65 名研究生和本科生**完成了这门课，**两人一组**完成 **33 个 ASIC 项目**。其中 **30 个产出了可行的版图**，并且 **18 个**基于其设计和实现上的改进被选为**流片候选**。可用经费允许其中**最好的 5 个设计在 2025 年 8 月送去制造** —— 包括**串行通信外设**、一个**扩展的 DMA 引擎**，以及一个**椭圆曲线密码（ECC）加速器**。

**MLEM** —— 一个基于 Croc SoC 平台的首个演示芯片 —— 已经在硅片上成功完成测试。在典型条件下，我们的演示芯片运行在 **82 MHz**，在执行整数运算时于 **1.2 V 核心电压下消耗 52.3 mW**，这与"在相似工艺下实现的商业和先进研究芯片"所报告的性能指标**相当**[12,13]。带功耗标注的 **shmoo 图**见图 3。

## IV. 结论与展望（Conclusion and Outlook）

我们展示了基于 **Croc RISC-V SoC** 的**端到端开源参考实现流程**在重构后的 VLSI 课程第一轮迭代中的成果。Croc **弥合了教学与产业之间的鸿沟**，让学生获得在 IC 的**设计、实现和测试**方面的动手经验。

测量结果表明：**Croc 足以运行真正的微控制器级别的工作负载**，并且它的**基础硅片指标与在类似成熟工艺节点上的商业和研究芯片相当**。

在 2025 年，这门 VLSI 课以 **65 名学生**在 ETH Zurich 开课，产出了 **30 个成功的开源 ASIC 版图**，其中 **5 个 SoC 使用 IHP 的 130nm PDK 完成流片**。

综合来看，这些结果说明：**开源工具、开源 PDK，加上一个精心设计的、可扩展的 SoC 模板，可以让动手做芯片设计的教育变得更容易获得、更容易规模化，并且更贴近工业实践。**

# 第 2 部分：术语大辞典（按类别）

## 2.1 芯片设计流程类

| 术语 | 中文 | 是什么意思 | 在本文中 |
|---|---|---|---|
| **VLSI** | 超大规模集成电路 | Very Large Scale Integration，指把几十万到几十亿个晶体管集成在一颗芯片上的技术，也常用来泛指"芯片设计"这门学科 | 论文标题里的"VLSI 课程"就是"芯片设计课" |
| **RTL** | 寄存器传输级 | Register Transfer Level。用硬件描述语言（这里是 SystemVerilog）写的代码，描述"数据在寄存器之间怎么流动、怎么被运算"。**它还是代码，不是电路图** | 学生写的就是 RTL；Croc 提供 RTL |
| **SystemVerilog** | — | 一种硬件描述语言（HDL）。长得像 C/Java，但描述的是电路而不是程序执行 | Croc 全部 IP 都用 SystemVerilog 写 |
| **GDS / GDSII** | 版图文件 | 芯片的最终"施工图"格式，记录每一层的几何图形。交给晶圆厂的光罩厂（mask shop）就是这个 | 图 1 就是学生 GDS 的渲染图 |
| **PDK** | 工艺设计套件 | Process Design Kit。晶圆厂给的一整套资料：有哪些"标准单元"（零件）、每个单元的面积/延时/功耗、物理尺寸（LEF）、制造规则（DRC 规则）等。**没有 PDK 就没法设计芯片** | 论文用的是 **IHP 130nm 开源 PDK**，不需要签 NDA |
| **EDA** | 电子设计自动化 | Electronic Design Automation，指所有用来设计芯片的软件工具 | 论文强调用**开源 EDA** 取代商业 EDA |
| **综合（Synthesis）** | 逻辑综合 | 把 RTL 代码"翻译"成由真实门电路（与非门、或门、触发器…）组成的**网表**的过程 | 用 **Yosys** 完成 |
| **网表（Netlist）** | — | 一张"零件清单 + 连线表"：用了哪些门、每个门的引脚怎么连 | 综合的输出 |
| **标准单元（Standard Cell）** | — | 工艺库里预先设计好的基本电路块，如与门、或门、非门、触发器（DFF）、缓冲器。芯片就是由成千上万个标准单元拼出来的 | IHP 库里的单元叫 `sg13g2_*`，比如 `sg13g2_nand2_1` |
| **PnR / 布局布线** | Place and Route | 决定每个标准单元放在芯片的哪个 (x, y) 坐标（布局），以及用金属线把它们连起来（布线） | 用 **OpenROAD** 完成（本次未跑） |
| **DRC** | 设计规则检查 | Design Rule Check。检查版图是否符合晶圆厂的制造规则（线太细？间距太小？） | "30 个 DRC 干净"就是说这 30 个版图工厂能做出来 |
| **LVS** | 版图与原理图一致性检查 | Layout vs Schematic。检查画出来的版图，其电路连接是否和你设计的网表一致 | 流片前必做的检查 |
| **Tapeout / 流片** | — | 把最终 GDS 交给晶圆厂去制造（字面意思："把磁带拿出来"，历史遗留说法） | 论文里 5 个设计真的去流片了 |
| **版图（Layout）** | — | 芯片的物理图形，也就是所有单元的摆放和走线结果 | 图 1 |
| **时序（Timing）** | — | 信号从触发器出发、经过组合逻辑、到达下一个触发器需要的时间。它决定了芯片**最高能跑多快** | 基線 80 MHz，最好 95 MHz |
| **Setup / Hold** | 建立/保持时间 | 触发器对输入信号的时间要求，时序分析的核心概念 | — |
| **Shmoo 图** | — | 一张二维图：横轴电压、纵轴频率，标出"在哪个电压/频率组合下芯片还能正常工作"，常标上功耗 | 图 3 |
| **QoR** | 结果质量 | Quality of Results，指频率、面积、功耗、密度这些"设计做得好不好"的指标 | 表 I 的"QoR improvements" |
| **DFT** | 可测试性设计 | Design for Testability，在芯片里加一些专门用于测试的电路 | 脚本里出现过 `dft_tck_mux` 之类的名字 |
| **Silicon bring-up** | 硅片点亮 | 芯片回到实验室后，第一次上电、让它跑起来、验证它真的是好的 | 论文给每个小组发评估板做这件事 |

## 2.2 处理器 / 架构类

| 术语 | 中文 | 是什么意思 | 在本文中 |
|---|---|---|---|
| **SoC** | 系统级芯片 | System-on-Chip。把 CPU、内存、外设、总线等**整个系统**集成在一颗芯片上（而不是一块电路板上的多个芯片） | Croc 就是一个 SoC |
| **RISC-V** | — | 一个**开放、免费**的指令集架构（ISA）标准，任何人都能用它设计处理器，不用交授权费 | Croc 用的核就是 RISC-V 核 |
| **ISA** | 指令集架构 | Instruction Set Architecture。CPU 能执行哪些指令的规范，是软件与硬件之间的"契约" | 学生可以做**ISA 扩展**（给 CPU 加新指令） |
| **Core / 核** | 处理器核 | 芯片里真正执行指令的那部分电路 | Croc 用 **CVE2** 核 |
| **CVE2** | — | CV32E2 系列的缩写，一个由 OpenHW Group 维护的、工业级质量的开源 32 位 RISC-V 核 | Croc 域的主角 |
| **微控制器级别** | — | microcontroller-class，指性能/复杂度类似 Arduino、STM32 那种小 MCU，而不是手机/电脑的大 CPU | 论文说 Croc 能跑"微控制器级工作负载" |
| **IPC** | 每周期指令数 | Instructions Per Cycle。IPC=1 表示平均每个时钟周期执行 1 条指令 | Croc 的双 SRAM + 单周期互联让 CVE2 达到理想 1 IPC |
| **总线 / 交叉开关** | Bus / Crossbar | 芯片内部各模块之间传输数据的"公路系统"。Crossbar 允许多对主从设备并行通信 | Croc 用 **OBI** 交叉开关 |
| **OBI** | 开放总线接口 | Open Bus Interface，OpenHW Group 定义的一个简单、开源的总线协议 | Croc 的骨干总线 |
| **Manager / Subordinate** | 主/从端口 | 总线上的"发起请求的一方"和"响应请求的一方"（旧的叫法 master/slave） | 用户域把这两个口暴露给学生 |
| **SRAM** | 静态随机存取存储器 | 芯片内部的存储器，速度快、掉电丢失 | Croc 有 2 个 SRAM bank；论文基线 8 kB、最好 32 kB |
| **Bank** | 存储体 | 把存储器分成几块，可以并行访问 | Croc 有 Bank 0 / Bank 1 |
| **外设（Peripheral）** | — | CPU 之外的功能模块，用来和外部世界交互 | GPIO、UART、Timer |
| **GPIO** | 通用输入输出 | General Purpose I/O。可以由程序控制高低电平的引脚，点灯、读按键都用它 | Croc 有 32 个 GPIO |
| **UART** | 串口 | 一种最基础的串行通信接口，常用作"打印调试信息"的通道 | 我们的仿真就是通过 UART 收到 "Hello World from Croc!" |
| **Timer** | 定时器 | 计时/产生周期性中断的模块 | Croc 里有 `obi_timer` |
| **CLINT** | 核心本地中断控制器 | Core-Local Interruptor，负责给 RISC-V 核发定时器中断和软件中断 | 仿真日志里的 "Waking core via CLINT msip" |
| **Bootrom** | 启动只读存储器 | 芯片上电后首先执行的一小段固化程序 | Croc 有 bootrom |
| **JTAG** | 调试接口 | 一种标准的芯片调试/测试接口，用来下载程序、读写内存、设断点 | 仿真里固件就是通过 JTAG 灌进 SRAM 的 |
| **Debug / DM** | 调试模块 | Debug Module，实现 JTAG 调试功能的硬件 | Croc 里有 `dm_top`、`dmi_jtag` |
| **DMA / iDMA** | 直接存储器访问 | 不经过 CPU、直接在外设和内存之间搬运数据的模块，能大幅提速 | 用户域里预置了一个 iDMA；有个学生项目就是扩展它 |
| **中断（Interrupt / IRQ）** | — | 外部事件打断 CPU 当前执行、转而处理紧急事务的机制 | Croc 给用户域提供自定义中断 |
| **CDC** | 跨时钟域 | Clock Domain Crossing。当信号从一个时钟域传到另一个时钟域时，需要用同步器避免亚稳态 | Croc 里有大量 `cdc_2phase`、`cdc_4phase`、`sync` 模块 |
| **PLL / 时钟** | — | 产生/倍频时钟信号的电路 | 仿真里默认 20 MHz |
| **复位（Reset）** | — | 把电路恢复到已知初始状态的信号 | Croc 里有 rstgen |

## 2.3 Croc 特有的概念

| 术语 | 解释 |
|---|---|
| **Croc 域（Croc domain）** | 芯片的"固定基础设施"部分：CVE2 核 + OBI 交叉开关 + 2 个 SRAM + 最小外设集。学生主要在它之上做开发，也可以改它 |
| **用户域（User domain）** | 专门留给学生放自己设计的区域。它已经把 OBI 的 manager/subordinate 口和自定义中断接好，学生只要往里塞模块就能挂到总线上 |
| **iDMA** | Croc 里预置的一个开源 DMA 引擎（来自 PULP 平台），学生可以直接用或扩展它 |
| **MLEM** | 论文里第一个被点亮并测试 silicon 的 Croc 演示芯片名字。82 MHz、52.3 mW @1.2 V |
| **DUTCTL** | 一个用于芯片测试的工具框架（DUT = Device Under Test，被测器件），用来在评估板上控制和测量芯片 |
| **DSA** | 领域定制架构（Domain-Specific Architecture）。为某一类应用（如加密、AI 推理）专门设计的硬件加速器。33 个项目里有 15 个是 DSA 加速器 |
| **ECC 加速器** | 椭圆曲线密码（Elliptic Curve Cryptography）加速器，5 个流片项目之一 |

# 第 3 部分：用大白话讲，这篇论文在干什么

## 3.1 一句话版本

**他们造了一个"开源的教学用芯片模板"，配上一条"全开源的造芯片流水线"，然后让 65 个本科生真的把自己设计的芯片送进工厂造了出来 —— 证明芯片设计课不需要商业软件也能开。**

## 3.2 拆成三步看

### 第一步：做一个"半成品芯片"给学生（Croc SoC）

直接让学生从零设计一颗能跑程序的芯片太难了：CPU、内存、总线、外设都得自己写，一学期根本做不完。

所以 ETH 做了一个**"半成品"**：

```
┌─────────────── Croc SoC ───────────────┐
│                                         │
│   ┌──────── Croc 域（已经做好）───────┐  │
│   │  CVE2 处理器核                     │  │
│   │  OBI 交叉开关（总线）              │  │
│   │  SRAM Bank 0 + Bank 1（内存）      │  │
│   │  GPIO / UART / Timer / CLINT       │  │
│   │  Bootrom / Debug(JTAG)             │  │
│   └────────────────────────────────────┘  │
│                  ↕ OBI 总线 + 中断        │
│   ┌──────── 用户域（空着，给你填）───┐  │
│   │                                     │  │
│   │         Your Design  ← 学生写       │  │
│   │      （加速器 / 协处理器 / 外设）   │  │
│   └────────────────────────────────────┘  │
└─────────────────────────────────────────┘
```

这样学生一上来就有**一颗能跑 C 程序的完整芯片**，只需要专注做自己那部分创新。想更硬核的，还可以去改 Croc 域（比如给 CPU 加指令）。

### 第二步：做一条"全开源流水线"（RTL → GDS）

学生写完后，要把它变成真的芯片：

| 阶段 | 工具 | 输入 → 输出 |
|---|---|---|
| 1. 收集源码 | **Bender** | 一堆 Git 仓库 → 一个源文件列表 |
| 2. 写软件 | **riscv gcc** | C 代码 → 芯片能跑的机器码 `.hex` |
| 3. **前端**：功能仿真 | **Verilator** | RTL + `.hex` → "程序跑得对不对" |
| 4. **后端**：逻辑综合 | **Yosys**（+ sv-elab + ABC） | RTL + PDK → 门级网表 |
| 5. 后端：布局布线 | **OpenROAD** | 网表 → 物理版图 |
| 6. 后端：出图 | **KLayout** | 版图 → GDS → 送工厂 |

**关键点**：这条线上**没有一个商业软件**，工艺库也是开源的。这就是论文的核心主张。

### 第三步：真的开课、真的流片，用结果说话

- 65 人 / 33 组 → 30 组做出能制造的版图 → 18 组入选 → **5 颗真的造出来了**
- 第一颗（MLEM）在实验室点亮：**82 MHz、52.3 mW**
- 对比：这个性能和商用 MCU（如 NXP LPC111x）在一个量级

**这就是论文的论据**：不是"我们觉得开源工具能用"，而是"学生用它造出了和商用芯片同量级的真芯片"。

## 3.3 为什么这件事重要

1. **降门槛**：不用买几百万的 EDA 授权、不用签 NDA，任何学校都能开课。
2. **可复现、可迁移**：所有东西开源 + CC 授权，别的学校直接拿去用。
3. **贴近工业**：用到的 RTL-to-GDS 流程和产业界是同一套思路，学生学的就是工作要用的。
4. **可扩展**：模板留了明确的"用户域"接口，学生创新空间大，老师批改也有统一基准。

# 第 4 部分：我是怎么复现的（新手可跟着做）

## 4.0 我的机器环境（以及为什么这么麻烦）

| 项目 | 情况 |
|---|---|
| 操作系统 | Windows |
| WSL / Linux | ❌ 没有（且 `wsl.exe` 被安全策略拦截） |
| Docker | ❌ 没有 |
| 解决方案 | 用 **MSYS2 UCRT64** —— 一个在 Windows 上提供 Linux 工具和开发环境的环境 |

> **给新手的提醒**：Croc 官方推荐的玩法是 Linux 或 IIC-OSIC-TOOLS 容器，非常省事。我这台机器没有这些条件，所以是在 Windows 上"硬凑"了一套工具链，**踩的坑基本都是 Windows 特有的**。如果你有 Linux/WSL，复制官方步骤即可，会轻松很多。

## 4.1 第一步：装工具

在 MSYS2 的 UCRT64 环境里安装：

```bash
pacman -S mingw-w64-ucrt64-verilator   # 仿真器
pacman -S mingw-w64-ucrt64-yosys       # 综合工具（注意：只在 ucrt64 仓库有，mingw64 没有）
pacman -S mingw-w64-ucrt64-riscv64-unknown-elf-gcc   # 交叉编译器
pacman -S make cmake ninja git python
```

**为什么用 UCRT64 而不是 MINGW64？** 因为 yosys 这个包只存在于 UCRT64 仓库里，我一开始在 mingw64 里装失败了才发现的。

另外还要一个 **Bender**（依赖管理器），MSYS2 里没有，得去 GitHub 下载原生 exe。

## 4.2 第二步：拿到代码

```bash
git clone --recursive https://github.com/pulp-platform/croc.git
```

`--recursive` 很重要：Croc 依赖很多子仓库（CVE2 核、外设 IP、PDK…），不递归克隆会缺一堆东西。最终 862 MB、957 个文件。

目录结构（你只需要关心这几个）：

```
croc/
├── rtl/          ← 芯片的 SystemVerilog 源码（重点）
├── sw/           ← 跑在芯片上的 C 程序（helloworld 等）
├── verilator/    ← 前端仿真脚本
├── yosys/        ← 后端综合脚本
├── openroad/     ← 布局布线脚本（我没跑）
├── ihp13/        ← IHP 130nm PDK 和 IP
├── env.sh        ← 环境配置（设置工具路径、PDK 位置）
└── Bender.yml    ← 依赖清单
```

## 4.3 第三步：编译一个跑在芯片上的程序（软件侧）

芯片没有操作系统，程序要直接编译成机器码：

```bash
cd croc/sw
make SELECT_PROJECT=helloworld
```

**发生了什么**：`riscv64-unknown-elf-gcc` 把 `helloworld.c` 编译成 RISC-V 指令集的机器码，再转成 `.hex` 文本文件（每行一个 32 位字）。这个 `.hex` 等下会被"塞进"仿真里的 SRAM，当作程序存储器。

产物：`sw/bin/helloworld.hex`

## 4.4 第四步：前端 —— Verilator 仿真

### 这一步在干什么？

**验证"我写的电路功能对不对"。**

Verilator 的做法很聪明：它不解释执行你的 Verilog，而是**把 SystemVerilog 翻译成一个 C++ 程序**，每个时钟周期推进一次状态，然后编译运行。所以速度极快。

### 命令

```bash
cd croc/verilator
./run_verilator.sh --build                        # 编译仿真模型（约 4 分钟）
./run_verilator.sh --run ../sw/bin/helloworld.hex # 加载固件运行
```

背后其实做了三件事：
1. `bender` 生成 RTL 文件列表
2. `verilator --binary` 生成可执行的仿真模型
3. 运行它，并加载 `.hex`

### 我看到的输出（这就是成功标志）

```
@     42050ns | [JTAG] Initialization success
@     42050ns | [JTAG] Writing 0x12345678 to 0x10000000
@     94600ns | [JTAG] Read 0x12345678 from 0x10000000
@     94600ns | [JTAG] Read back correct data          ← JTAG 通路验证通过
@     94600ns | [JTAG] Loading binary from ../sw/bin/helloworld.hex
@    106100ns | [JTAG] Writing to memory @1000000c     ← 固件被写进 SRAM
@   1401000ns | [CORE] Waking core via CLINT msip      ← 通过中断唤醒 CPU
@   1439700ns | [CORE] Wait for end of code...
@   3461800ns | [UART] Hello World from Croc!          ← 程序真的跑起来了！
@   3488950ns | [JTAG] Simulation finished: SUCCESS
```

**怎么读懂它**（对新手很重要）：

| 行 | 含义 |
|---|---|
| `[JTAG] ... Read back correct data` | 测试台先通过调试接口读写内存，确认通路是好的 |
| `Loading binary from ...helloworld.hex` | 把程序灌进芯片的内存 |
| `Waking core via CLINT msip` | 通过中断告诉 CPU："可以开始跑了" |
| `[UART] Hello World from Croc!` | CPU 执行了程序，通过串口把字符串发了出来 |
| `Simulation finished: SUCCESS` | 测试台判定：功能和预期一致 |

**这一步证明了**：Croc 的 RTL 是能跑的，CPU 能取指、能执行、能通过外设输出。

### 我踩的坑（Windows 专属）

1. **Bender 输出 `D:\xxx` 反斜杠路径**，而 croc 的脚本用 Linux 风格路径做字符串替换，替换失败 → 找不到模块。
   → 解决：写了个 wrapper 脚本，把 `D:\` 转成 `/d/`、把 `\` 转成 `/`。

2. **编译时报 "Permission denied"**：gcc 的临时目录不可写。
   → 解决：把 `TMPDIR/TMP/TEMP` 指到 `D:/croc_work/tmp`。

3. **链接时报 `std::__cxx11::basic_string` 未定义**：MSYS2 的 GCC 16 + libstdc++ 打包有问题，在 `-O1/-O2/-O3` 下会缺符号。
   → 解决：用 `-O0`（不优化）全量重编：
   ```bash
   cd obj_dir_rtl
   make -f Vtb_croc_soc.mk -B OPT_FAST=-O0 OPT_GLOBAL=-O0 OPT_SLOW=-O0 -j 8
   ```

## 4.5 第五步：后端 —— Yosys 综合

### 这一步在干什么？

**验证"这个设计能不能真的用这个工艺造出来，代价多大"。**

前端仿真是"逻辑世界"的事：只有 0 和 1、只有周期数，**没有面积、没有延时、没有功耗**。
后端要做的是：把你写的 `always_ff`、`a + b` 这些抽象描述，**替换成 IHP 130nm 工艺库里真实存在的门电路**。

比如你写 `assign y = a & b;`，综合器会选一个 `sg13g2_and2_1`（二输入与门），并且知道它**面积 17 µm²、延时 0.05 ns**。

### 前置：必须先有 sv-elab 插件

Yosys 自带的 Verilog 前端对 SystemVerilog 支持不够，croc 用的是 **sv-elab（yosys-slang）插件**，通过 `read_slang` 命令读源码。

我装的 yosys 是 0.66，里面**没有**内置这个功能，所以要自己编译插件：

```bash
git clone https://github.com/povik/sv-elab.git
cd sv-elab
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 8        # 约 5 分钟
cp build/slang.so <yosys的datdir>/plugins/
```

验证装好了：


### 命令

```bash

```

脚本内部流程：

```
bender 生成 croc.flist（源文件列表）
   ↓
读入 Liberty 库（标准单元 + SRAM + IO 的时序/面积数据）
   ↓
read_slang 解析 SystemVerilog（sv-elab 插件）
   ↓
给指定模块打 keep_hierarchy（保留层次，方便调试和后继流程）
   ↓
dfflibmap：把抽象的触发器映射到工艺库里真实的触发器
   ↓
abc -D 10000：以 10 ns（100 MHz）为目标做逻辑优化和工艺映射
   ↓
输出：门级网表 + 面积/寄存器/时序报告
```

### 我踩的坑（Windows 专属，全是硬骨头）

1. **`kernel/rtlil.h` 找不到**
   根因：yosys-config 返回的是 MSYS 风格路径 `/ucrt64/share/yosys/include`，但 ninja 和 g++ 是**原生 Windows 程序，不会做 MSYS 路径转换**，于是 GCC 把它当成 `D:/ucrt64/...`（不存在）。
   → 解决：改 `cmake/FindYosys.cmake`，用 `cygpath -m` 把所有 `-I/-L` 和裸路径转成 `D:/croc_work/tools/msys64/ucrt64/...`。

2. **`std::_snprintf` 不是 `std` 的成员**
   根因：yosys 为了兼容 MSVC，在头文件里写了 `#define snprintf _snprintf`。这个宏把 slang 依赖的 boost 头文件里的 `std::snprintf` 改成了不存在的 `std::_snprintf`。
   → 解决：新建一个 `yosys_win_compat.h`，用 `-include` 强制每个源文件先包含它 —— 它先 include yosys 头文件，再把那些宏 `#undef` 掉（MinGW 本来就有标准的 `snprintf`）。

3. **链接时找不到 `libgnat.a`**
   根因：yosys-config 里写死了 gcc 版本号 `16.1.0`，本机装的是 `16.2.0`。
   → 解决：在 CMake 里加"路径不存在时用通配符 glob 回退"的逻辑，自动找到 16.2.0 的库。

4. **`--ignore-unknown-modules` 选项不存在**
   根因：我拉的是 sv-elab 最新版，这个选项已经被移除了，而 croc 的 tcl 脚本还在用。
   → 解决：从 `yosys/scripts/yosys_synthesis.tcl` 的 `read_slang` 命令行里删掉这个选项（新版改用 `--blackboxed-module` 或预加载 blackbox）。

## 4.6 第六步（加分项）：门级网表再仿真一次

# 第 6 部分：给新手的延伸阅读建议

1. **先学一点 Verilog/SystemVerilog**，哪怕只看懂 `module / always_ff / assign` 三个关键字，就能大致读懂 `rtl/` 里的代码。
2. **从 `sw/` 开始玩**：改改 `helloworld.c`，重新编译、重新仿真，看 UART 输出变化 —— 这是最快获得正反馈的路径。
3. **看仿真日志比看代码更容易入门**：日志里 JTAG/UART/CLINT 的行为，能帮你把"CPU、内存、外设"这些抽象概念串起来。
4. **对比 area report**：综合一次，记下单元数和面积；然后改动 RTL（比如加一个寄存器）再综合一次，看数字怎么变 —— 这能建立"代码 → 硬件代价"的直觉。
5. **想跑完整流程**：装 WSL（Ubuntu）或 Docker，直接用 IIC-OSIC-TOOLS，就能把 OpenROAD 和 KLayout 也跑完，一直做到 GDS。
