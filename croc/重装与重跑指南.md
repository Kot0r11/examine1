## 二、这次重装踩到的坑（都已在脚本里修好）

1. **包名不是 `mingw-w64-ucrt64-xxx`**
   UCRT64 环境的包名前缀是 `mingw-w64-ucrt-x86_64-`。写错会报 `target not found`。
   查真名的办法：`pacman -Ss verilator`

2. **清华镜像会 403 拒绝下载包文件**
   数据库能下、包文件全部 403。改用南大镜像（实测最快，0.12 秒响应），
   脚本里还配了中科大、华为云作为备用。

3. **Verilator 缺 LZ4**
   生成 FST 波形需要 LZ4，但 MSYS2 的 verilator 包不会自动装它，
   报错是 `fatal error: lz4.h: No such file or directory`。
   要单独装 `mingw-w64-ucrt-x86_64-lz4`。

4. **旧的 `obj_dir_rtl` 会残留旧工具链路径**
   这个目录是 Verilator 的构建产物，里面记着上次用的工具链路径。
   换了安装位置后会报 `No rule to make target 'D:/croc_work/tools/msys64/.../verilated.cpp'`。
   处理办法：把它改名（不要删），让 Verilator 重新生成一份。

5. **链接时缺 `std::__cxx11::basic_string` 符号**（不是新坑，但每次都会遇到）
   MSYS2 的 GCC 16 在 `-O1/-O2/-O3` 下链接会缺符号，加 `-lstdc++` 也没用，是打包问题。
   解决办法是用 `-O0` 全量重编：

   ```bash
   cd obj_dir_rtl
   make -f Vtb_croc_soc.mk -B OPT_FAST=-O0 OPT_GLOBAL=-O0 OPT_SLOW=-O0 -j 8
   ```

## 三、从零重装的完整步骤

### 第 1 步：装 MSYS2 基础包（41 MB）

```powershell
$env:MSYSTEM='UCRT64'
# 下载官方基础包（走本机代理，因为 GitHub 的 443 不挂代理时不通）
curl.exe -L --proxy http://127.0.0.1:7897 -o D:\croc_setup\msys2-base.tar.xz https://github.com/msys2/msys2-installer/releases/download/nightly-x86_64/msys2-base-x86_64-latest.tar.xz
# 解压到 D 盘根目录（包内自带 msys64/ 顶层目录，解完正好就是 D:\msys64）
tar.exe -xf D:\croc_setup\msys2-base.tar.xz -C "D:\"
```

成功标志：`D:\msys64\usr\bin\bash.exe` 存在。

### 第 2 步：装工具链（下载 365 MB，安装后 2.4 GB）

```powershell
$env:MSYSTEM='UCRT64'
& 'D:\msys64\usr\bin\bash.exe' -lc '/c/Users/zhengxy/Desktop/examine1/croc/setup/install-toolchain.sh'
```

成功标志（脚本最后会自己打印）：

```
verilator  : Verilator 5.050 2026-07-01
yosys      : Yosys 0.66
riscv-gcc  : riscv64-unknown-elf-gcc.exe (GCC) 16.1.0
make 4.4.1 / cmake 4.4.3 / ninja 1.13.2
```

### 第 3 步：装 sv-elab 插件（Yosys 读 SystemVerilog 必须用它）

插件已经编译好放在 `D:\workbuddy\croc_work\src\sv-elab\build\slang.so`（14.2 MB），
复制到 Yosys 的插件目录即可（版本同为 0.66，直接可用）：

```bash
mkdir -p /d/msys64/ucrt64/share/yosys/plugins
cp /d/workbuddy/croc_work/src/sv-elab/build/slang.so /d/msys64/ucrt64/share/yosys/plugins/
```

验证：

```bash
yosys -p "plugin -i slang.so; help read_slang"
```

能打印出 `read_slang` 的用法，就说明插件装好了。

> 以后如果要重新编译插件：源码在 `D:\workbuddy\croc_work\src\sv-elab`，
> 里面已经包含之前的三个 Windows 补丁（`FindYosys.cmake` 的路径转换、
> `yosys_win_compat.h` 去掉 MSVC 宏、libgnat 版本回退）。

## 四、亲手重跑一遍（一条命令）

```powershell
$env:MSYSTEM='UCRT64'
& 'D:\msys64\usr\bin\bash.exe' -lc '/d/workbuddy/croc_work/rebuild-and-run.sh'
```

脚本依次做三件事，每步都有明确的成功标志：

| 步骤 | 命令 | 成功标志 |
|---|---|---|
| 1 编译软件 | `cd sw && make SELECT_PROJECT=helloworld` | 生成 `sw/bin/helloworld.hex` |
| 2 前端仿真 | `./run_verilator.sh --build` 再 `--run ../sw/bin/helloworld.hex` | 日志出现 `[UART] Hello World from Croc!` 和 `Simulation finished: SUCCESS` |
| 3 后端综合 | `cd ../yosys && ./run_synthesis.sh --synth` | `SYNTH_EXIT=0`，生成 `out/croc_yosys.v` 和 `reports/*.rpt` |

本次重跑的真实结果（2026-09-29 00:02 到 00:05）：

```
1. bin/helloworld.hex                    6,931 字节
2. obj_dir_rtl/Vtb_croc_soc.exe          7,370,599 字节
   @  94600ns | [JTAG] Loading binary from ../sw/bin/helloworld.hex
   @ 3461800ns | [UART] Hello World from Croc!
   @ 3488950ns | [JTAG] Simulation finished: SUCCESS
3. out/croc_yosys.v                      4,494,142 字节

```

注意第 2 步的时间戳 **3,461,800 ns**，和 9 月 18 日那次完全一样。
这不是巧合：仿真里没有随机因素，同一份 RTL 加同一份固件，跑出来必然一致——
这本身就是结果可复现的证据。

## 五、每步到底在干什么（你要能自己讲出来的部分）

| 步骤 | 一句话解释 | 工具 |
|---|---|---|
| 编译软件 | 把 C 程序翻译成这颗芯片能执行的机器码 | riscv64-unknown-elf-gcc |
| 前端仿真 | 在电脑里假装芯片已经造好了，把程序灌进去看它跑得对不对 | Verilator |
| 后端综合 | 把 RTL 代码翻译成真实工艺库里存在的门电路，并算出面积 | Yosys + IHP 130nm PDK |

为什么芯片要先仿真再制造：流一次片要几百万、等几个月，做错了就是废片。
所以整个流程都在用软件把硬件预演到极致——仿真不是玩具，是工业流程里必须走的一关。

## 六、出问题时对照这张表

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `target not found` | 包名写错 | `pacman -Ss 关键字` 查真名，前缀是 `mingw-w64-ucrt-x86_64-` |
| 下载报 403 | 清华镜像拒绝 | 换南大镜像（脚本已默认） |
| `lz4.h: No such file` | 缺 LZ4 | `pacman -S mingw-w64-ucrt-x86_64-lz4` |
| `No rule to make target '...tools/msys64/...'` | `obj_dir_rtl` 残留旧路径 | 改名后重新构建 |
| `undefined reference to std::__cxx11::basic_string` | MSYS2 的 GCC 打包问题 | 用 `-O0` 全量重编 |
| `bender: command not found` | 没加载环境脚本 | 先 `source /d/workbuddy/croc_work/crocenv.sh` |
| `Permission denied` 写临时文件 | gcc 需要 Windows 风格临时目录 | 环境脚本里已设好 `TMP/TEMP/TMPDIR` |
