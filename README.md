## 扫雷：两个阶段怎么实现、怎么验证

### 阶段一：先做出"能自己玩"的版本

**怎么实现的**：一个 HTML 文件，JS 分成两层——**引擎**只管棋盘数据（哪格是雷、翻开没有、赢还是输），完全不碰网页元素；**界面**只负责画出来，以及把鼠标/触屏操作翻译成引擎调用。分层是为了阶段二能把引擎单独抽出来做批量测试。
经典外观全部用 CSS 边框做出来：未翻开的格子"左上亮、右下暗"看着是凸的，已翻开的去掉立体感，计数器反过来做成凹的，数字 1–8 用经典配色。

**怎么验证的**（ai自己验证自己跑的）

1. 静态检查（`node tools/check-game.js`）：把文件里的 JavaScript 交给 Node.js 做语法编译检查（只看能不能通过语法解析，不执行），再检查 HTML 标签是否成对、界面代码引用的 37 个元素 id 是否都真实存在、任务书要求的功能关键词是否齐全——全部通过
2. 界面层测试（`node tools/test-ui.js`）：这一层是补上的。它用一个极简的假 DOM 把整个游戏跑起来，然后**真的去"点"格子**，检查数据变化之后界面有没有跟着更新。目前 25 项断言全部通过，覆盖"点数字展开周围"、"切换角色主题并存进本地"、"列出该角色的卡面"、"通关后所有雷都被标出来"、"战绩只保留最近 10 局"、"AI 打完一局不会自动停"、"切难度后棋盘尺寸正确"、"自定义雷数超限时不开局"等
3. 卡面地址校验（`node tools/verify-cards.js 40`）：内置卡面是按"资源编号"拼地址的，编号错一位就会变成碎图。脚本会逐个请求并检查**文件头是不是 PNG**（那个站点对不存在的路径也返回 200，只查状态码没有意义）。抽查 40 位角色各一张：**40/40 成功**
4. 手动试玩（这一步必须在浏览器里做，代码检查代替不了画面）：左键翻开、右键插旗、点数字快速展开、故意踩雷看失败表现、赢一局看是否出现 😎 并自动标出所有雷、切主题后按 F5 刷新看是否保留、切难度看棋盘尺寸对不对、把窗口缩小到手机宽度看布局有没有溢出

### 阶段二：让 AI 来玩（自动演示）

**硬指标**：AI 自动完成 9×9、10 雷标准局，翻开全部安全格且不踩雷，随机雷区连续通关 2 局。

**怎么实现的**：三层求解器，能推理就不猜——

1. **基础规则**：某个数字周围的雷已全部插旗 → 剩下的未知格必然安全；未知格数正好等于剩余雷数 → 它们全是雷
2. **子集规则**：数字 A 的未知格被数字 B 包含时，"B 比 A 多出来的格子"里的雷数 = B − A，常常能再推出确定结论
3. **概率计算**：推不动了就穷举边界格的所有合法布雷方式，结合"全盘还剩几颗雷"算出每格是雷的概率，挑最低的翻开；有完全没线索的区域时优先去开新区域。开局优先点角（相邻格少，猜错代价低）

**怎么验证的**：把引擎抽出来批量模拟（`node tools/simulate-minesweeper.js 2000`），不看"好像都能赢"，用数据说话：

| 指标 | 结果 |
|---|---|
| 总胜率 | **95.8%**（1915 / 2000） |
| 最长连胜 | **72 局** |
| 首次达成"连续通关 2 局" | 第 2 局 |
| 200 次"从零开始打到连胜 2 局" | **200/200 成功**，平均 2.10 局 |

## 进阶挑战：复现 Croc 开源芯片项目

二选一里我选了第二项，完整记录在 [`croc/`](croc/README.md)，这里只讲核心。

**论文讲什么**：传统上教芯片设计要用几百万的商业软件、还要签保密协议才能拿到工艺库，只有少数学校开得起课。ETH Zurich 用开源的 RISC-V 芯片模板 Croc，配一条**全开源**的设计流程和 130nm 开源工艺库，让普通学校也能开"真的把芯片造出来"的课——他们一届 65 个学生做的 33 个项目里，**5 颗真的流片了**。

**我跑通了流程里的两段**（芯片设计是一条流水线，前端和后端是其中两道工序）：

| 阶段 | 干什么 | 工具 | 我的结果 |
|---|---|---|---|
| 前端 | 在电脑里"假装芯片已经造好"，把程序灌进去看功能对不对 | Verilator | 串口打印出 `Hello World from Croc!`，仿真判定 `SUCCESS` |
| 后端 | 把 RTL 翻译成真实工艺库里的门电路，算出面积代价 | Yosys + IHP 130nm PDK | 门级网表 31,016 个标准单元、面积 1.58 mm² |
| 闭环验证 | 用综合出的门级网表再仿真一次 | Verilator | 同样打印 `Hello World`，**输出时刻与 RTL 仿真完全一致（3,461,800 ns）** |

最后一行是关键：它证明**综合没有改变电路功能**。芯片不能像软件那样试错——流一次片要几百万、等几个月，所以整条流程都在用软件把硬件预演到极致，**仿真不是玩具，是工业流程里必须走的一关**。

> 没做的部分如实说明：OpenROAD 布局布线和 KLayout 出 GDS 在 Windows 上装不了（需要 WSL 或官方容器）。任务书要求"后端至少完成其一"，我用 Yosys 综合完成了后端。

## 踩过的坑

1. **GitHub 的 HTTPS 端口被网络阻断，`git push` 一直超时**：报错是 `Failed to connect to github.com:443 after 21040 ms`。逐个测试后发现 `github.com:443` 不通，但 `github.com:22`（SSH）和本机代理端口是通的，最后让 Git 走本机代理（`git config --global http.proxy`）才推上去。**本质其实应该是校园网的问题，有时候上不去挂一下梯子又可以提交了**
2. **邮箱链接点开是空白页**：网页里的 `mailto:` 写法本身没错，它的作用是"调用系统的默认邮件程序"。后面才发现我电脑因为没有下这种软件，所以浏览器无处可去，只能开一个空白标签页。解决办法是保留 `mailto:`（访客装了邮件客户端就能正常用），另外加一个「复制」按钮兜底
3. **`git status` 里中文文件名是乱码**：那是 Git 的转义显示，不是文件坏了，`git config --global core.quotepath false` 就能正常显示
4. **提交时提示 `LF will be replaced by CRLF`**：Windows 和 Linux 换行符不同，Git 在做自动转换，不影响功能
5. **点数字没反应（最难找的一个 bug）**：扫雷里"点已翻开的数字一次展开周围"是标准操作，但我一开始怎么点都没反应。AI 第一反应是判断"我没插旗，属于正常规则"——但我确实插了旗。后来重查代码才找到真因：**左键点数字时确实调用了展开函数，却忘了调用界面刷新**，所以数据变了、屏幕没重画。AI 的修复办法是把所有玩家操作统一收进一个入口函数（执行 → 重画 → 计时 → 结算），从根上杜绝"漏掉重画"；另外加了一个界面层测试，专门盯这类问题
6. **卡面图片地址不能靠猜**：按规律拼出来的地址请求都返回 200，但内容其实是网页。后来去读卡片数据里的 `resourceSetName` 字段，才拿到真实地址
7. **AI 的"最长连胜"永远停在 2**：因为我把 AI 演示写成了"连续通关 2 局就自动停下"，又在每次重新开始时把连胜清零——两个设定叠在一起，最长连胜就再也涨不上去了。改成：**连胜只有 AI 踩雷才中断**，中途按停再开始不清零；达到 2 局时只显示「✅ 已达标」，演示继续跑，连胜接着累积
8. **Windows 上跑 Croc 流程**：连踩 5 个坑（MSYS2 包名前缀、镜像 403、缺 LZ4、旧构建目录残留、libstdc++ 链接缺符号），详见 [croc/重装与重跑指南.md](croc/重装与重跑指南.md)

## 两处关键逻辑详解（防"纯粘贴"自查）

以下两段是 AI 生成代码里最关键的部分，也是我**能自己讲清楚**的：

### 1. 头像为什么不会被拉变形（`object-fit: cover`）

```css
.avatar {
  width: 110px; height: 110px; border-radius: 50%;
  object-fit: cover;             /* 按比例裁剪填满，不变形 */
  object-position: center top;   /* 裁剪时优先保留上方的头部 */
}
```

头像框是 110×110 的正方形，证件照是竖长方形，宽高比完全不同。**不写 `object-fit` 的话，浏览器默认按 `fill` 处理，会把照片强行拉伸成正方形，脸就被压扁了。** `cover` 的作用是保持原图比例放大到铺满方框、多出来的部分裁掉；`object-position: center top` 指定裁的时候以上方中心为基准，优先保住头顶和脸。`border-radius: 50%` 只是把方框四角切掉变成圆。

### 2. 时间线不用图片、也不用多余标签（`border-left` + `::before`）

```css
.timeline > li { position: relative; border-left: 2px solid #e5e7eb; padding: 0 0 18px 22px; }
.timeline > li::before {
  content: ""; position: absolute; left: -8px; top: 7px;
  width: 12px; height: 12px; border-radius: 50%; background: var(--accent);
}
```

每条履历是一个 `<li>`，给它一条左边框就是时间线的竖线；`position: relative` 把它变成"定位基准"，让里面的绝对定位元素以它为准。`::before` 是伪元素——**不用往 HTML 里加任何标签，就能凭空造出一个可设置样式的元素**，这里造的就是那个小圆点。`left: -8px` 把它往左挪一点，正好压在竖线上；最后一项把竖线设成透明，线就自然收尾。

## Git 与命令行速查

| 命令 | 用途 |

## 信息安全实践

**为什么选 MIT**（AI 帮我选的，我认可）：这是学习性质的个人作品，希望别人能自由查看、学习和使用，不用额外问我、也不限用途。MIT 是最简短宽松的常见协议，只要求保留版权声明、作者不担责；GPL 要求衍生作品也必须开源，对这种网页小项目约束太强。

**其他措施**：

- 开启 GitHub 两步验证（2FA），密码泄露也进不了账号

### 两条"AI 给过、但我查证后发现是错的"信息

#### 第一条：仓库地址根本没有被粘贴坏

AI 说我执行 `git push` 失败后，把终端输出发给 AI，它判断是我把仓库地址粘贴坏了——说地址前后混进了 Markdown 的方括号，变成 `[https://...](https://...)`，所以 Git 连不上，需要重新设置远程地址。

查证过程：我没有直接照着改，而是先执行 `git remote -v` 查看仓库里实际存的值。输出是：

```
origin  https://github.com/Kot0r11/examine1 (fetch)
origin  https://github.com/Kot0r11/examine1 (push)
```

结论：地址是干净的，根本没有方括号。那对括号是聊天窗口把网址自动渲染成超链接造成的显示效果，被 AI 误当成了真实内容。

真正的原因：梯子不知道为啥发癫了连不上，后面用校园网突然发现可以直连（话说校园网有时候可以连有时候又不可以）。AI 说是网络层面阻断了 `github.com` 的 443 端口，逐个测试后发现 `github.com:443` 超时不通，但 `github.com:22`（SSH）和本机代理是通的，所以改用代理才推送成功。

我的收获：不要相信"看起来像"的现象。判断问题要去看实际值——`git remote -v` 看真实地址、`git status` 看真实状态，而不是从报错的显示效果去猜。

#### 第二条：Bestdori 的卡面地址不能靠"规律"拼出来

AI 的说法：做角色主题时，AI 按社区常见的路径规律拼出了卡面图片地址，并用工具请求验证，返回的都是 200，于是判断"链接可用"。然后做出来没有什么作用。

查证过程：我没有直接采信，而是检查返回的内容本身——用 Python 读了一下，发现这些 200 全都不是图片，而是同一个网页；AI 又故意请求了一个不存在的文件名，同样返回 200。

结论：那个站点对任何路径都返回网页外壳，200 完全不能证明链接有效。"请求成功"不等于"拿到了想要的东西"，必须检查返回内容。

后来的进展：AI 当时的结论是"这个站点的图片地址没法可靠获得"，于是退而求其次，改成让我自己提供图片。但我又追问了一次，然后让它自己在 bestdori 里面找找，这次 AI 换了思路——卡片接口里有个 `resourceSetName` 字段，卡片 1 的值是 `res001001`，真实地址就是 `资源目录名 + _rip/card_normal.png`。按这个规律抽查 40 位角色，40/40 都是真图片，卡面选择功能这才真正做出来。

**我的收获**：
ai有时候骗人，得压力一下，通过连续追问逼问啥的才会往正确的方向想
